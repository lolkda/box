## 2. 目标与范围

### 背景

KernelSU WebView 中的管理页在点击按钮和上下滚动时出现明显延迟。Chrome DevTools Protocol 连接设备 WebView（KernelSU Manager v3.3.1、Android WebView Chrome/157）后测得：

- `box.tool task list --json` 每 1.5 秒执行一次，`ksu.exec()` 在 WebView 主线程同步阻塞约 1.45–1.55 秒。
- `box.tool status --json` 每 5 秒执行一次，单次阻塞约 330–440 毫秒。
- 日志页 `box.tool logs 200 --json` 每 2 秒执行一次，单次阻塞约 180–240 毫秒。
- Event Timing 记录的点击输入延迟为 744–1488 毫秒，与上述同步调用时间吻合。

根因是 `ksu.exec()` 的 JavaScript 接口在命令执行完成前不返回，阻塞整个 WebView 渲染线程；同时页面在全局布局中高频轮询任务、状态和日志，导致主线程长期不可用。CSS、点击事件处理和滚动容器不是本次确认的首要根因。

### 目标

- 将所有 shell 命令切换到 `ksu.spawn()` 异步执行，命令等待期间不阻塞 WebView 主线程。
- 任务列表只在存在运行中任务时轮询，空闲时停止。
- 服务状态只在概览页可见时刷新，其他页面复用缓存。
- 概览页不再显示最近日志；日志只在日志页按 2 秒刷新。
- 通过真机 Chrome DevTools 指标验证点击、长任务和滚动表现。

### 非目标

- 不兼容不提供 `ksu.spawn()` 的旧版 KernelSU；缺失时显示升级提示。
- 不修改 `box.tool task list` 或其他后端脚本。
- 不改变 `box.tool --json` 包络、任务生命周期、危险操作确认规则或视觉设计。
- 不包含 Git 提交、推送或真机模块替换；真机部署与验证需要单独授权。
- 不针对所有页面做无关的性能重写。

## 4. 行为要求与约束

### R-001：异步命令执行

- 参与者或触发方：管理页的所有 API 调用。
- 前置条件与输入：KernelSU WebView 提供 `ksu.spawn()`，命令通过 `/data/adb/box/scripts/box.tool` 或 `/data/adb/box/scripts/box.service` 执行。
- 必须满足的行为：所有命令使用 `ksu.spawn()` 启动；调用返回后立即让出主线程；stdout 和 stderr 按行收集并还原为现有 `{errno, stdout, stderr}` 结构；非零退出码交由现有错误解析处理。
- 输出或状态变化：`spawn` 调用本身在约 60ms 内返回；命令执行期间页面仍可渲染、响应点击和滚动。
- 边界与失败行为：`spawn` 无法启动、命令非零退出、输出无法解析时，仍通过现有 `ApiError` 或错误状态展示；临时文件在成功或失败后都尝试清理。

### R-002：KernelSU 能力检查

- 参与者或触发方：应用启动和每个需要执行命令的页面。
- 前置条件与输入：页面运行在 KernelSU WebView 中。
- 必须满足的行为：应用启动时同时检查 `window.ksu` 和 `window.ksu.spawn`；两者都存在才进入管理页；任一缺失都显示可读的升级或环境提示。
- 输出或状态变化：不发起任何 `exec()` 或查询请求；页面提示需要 KernelSU Manager 3.3 或更高版本。
- 边界与失败行为：不静默回退到同步 `exec()`，不允许出现未处理的 `ksu is not defined` 或 `spawn is not a function`。

### R-003：任务轮询

- 参与者或触发方：任务中心、任务角标、任务完成通知。
- 前置条件与输入：任务列表查询首次加载或任务状态发生变化。
- 必须满足的行为：应用启动或进入任务页时查询一次任务列表；任务列表中任意任务为 `running` 时每 2 秒轮询；没有运行中任务时停止轮询；启动任务成功后立即更新任务查询缓存并进入轮询。
- 输出或状态变化：任务运行期间角标和详情持续更新；任务完成时触发现有 toast 并刷新相关查询；空闲时不再周期性执行 `task list`。
- 边界与失败行为：任务启动失败不进入轮询；从命令行在应用空闲时启动的任务不保证自动发现，重新打开页面或手动刷新任务页后恢复。

### R-004：服务状态刷新

- 参与者或触发方：概览页、mihomo 专属页面守卫、核心配置页。
- 前置条件与输入：页面进入概览或需要判断当前核心。
- 必须满足的行为：概览页可见时每 15 秒刷新状态；离开概览后停止状态轮询；其他页面优先使用缓存；需要守卫的页面在缓存缺失时做一次按需查询；服务操作、设置保存和危险操作成功后主动 invalidate 状态。
- 输出或状态变化：概览状态最多滞后 15 秒；切换页面不产生无意义的 `status --json` 调用。
- 边界与失败行为：外部停止服务时不保证在 15 秒内被非概览页面发现；概览页按刷新周期更新。

### R-005：日志轮询

- 参与者或触发方：日志页。
- 前置条件与输入：日志页显示最近 200 行；概览页不显示日志摘要。
- 必须满足的行为：概览页不查询、不轮询日志；日志页保持每 2 秒刷新；页面不可见时不主动轮询。
- 输出或状态变化：概览页减少一次周期性日志读取；日志页保持现有实时性。
- 边界与失败行为：日志读取失败保留最后一次成功内容，并按现有错误状态处理。

### R-006：性能验收与测量

- 参与者或触发方：开发验证流程。
- 前置条件与输入：构建产物在设备 KernelSU WebView 中运行，Chrome DevTools Protocol 可用。
- 必须满足的行为：记录 `spawn` 调用同步耗时、Long Task、Event Timing 和滚动帧间隔；修复后空闲状态不得存在由业务命令造成的 100ms 以上长任务；点击后 100ms 内出现可见 loading 或按压反馈；概览和列表滚动无明显掉帧。
- 输出或状态变化：验证记录包含修复前后指标和具体测试页面。
- 边界与失败行为：若主线程长任务已消除但滚动仍掉帧，继续定位合成层或 `backdrop-filter` 等滚动路径问题；不得以主线程指标代替滚动验收。

### 相关约束

- 页面运行在 Android WebView，不能依赖桌面浏览器专属 API。
- 所有命令继续通过绝对路径调用，不新增本地 HTTP 服务。
- `webui/src` 是源码，`webroot` 是构建产物；不得直接手改 `webroot/assets`。
- 不修改 `box.tool` 的 JSON 契约、任务目录结构或现有 CLI 行为。
- 现有安全约束继续有效：订阅 URL、token 和 GitHub token 不写入日志、页面标题或错误详情。

## 5. 关键决定

### D-001：全部命令使用异步 spawn

- 状态：已确认
- 结论：所有查询和变更命令统一改用 `ksu.spawn()` 封装，不再在运行路径使用同步 `ksu.exec()`。
- 理由：实测 `exec()` 在设备上阻塞 0.5–1.5 秒，是点击和滚动卡顿的决定性原因；`spawn` 调用约 20–55ms 返回，命令在后台完成。
- 考虑过的备选：只改轮询类调用；只降低轮询频率。
- 未采用原因：前两者仍会在点击启动、停止或更新时冻结 UI。
- 影响范围：R-001、R-002、R-006。

### D-002：任务只在运行中轮询

- 状态：已确认
- 结论：任务列表启动时查询一次；存在 `running` 任务时每 2 秒轮询；无运行任务时停止；任务启动后主动写缓存。
- 理由：原先每 1.5 秒一次的 `task list` 是最大的单次阻塞来源，空闲时完全没必要执行。
- 考虑过的备选：固定低频轮询；仅手动刷新。
- 未采用原因：固定低频仍浪费 root shell；仅手动会丢失任务角标和完成通知。
- 影响范围：R-003。

### D-003：状态只在概览页刷新

- 状态：已确认
- 结论：概览页可见时每 15 秒刷新状态；其他页面使用缓存；操作后主动 invalidate。
- 理由：状态卡只存在于概览页，其他页面只需要一次性 core 判断，全局轮询没有收益。
- 考虑过的备选：全局每 15 秒刷新；只在进入页面和操作后刷新。
- 未采用原因：全局刷新浪费 root shell；完全事件驱动无法发现外部服务变化。
- 影响范围：R-004。

### D-004：概览日志 5 秒、日志页 2 秒

- 状态：已调整（2026-11-24）
- 结论：概览页不再显示日志；日志页保持每 2 秒刷新。
- 理由：概览不再需要日志摘要，去掉后可减少一次周期性 root shell 查询和页面高度。
- 考虑过的备选：概览保留 5 秒摘要；改为手动刷新。
- 未采用原因：用户明确要求概览页去掉最近日志。
- 影响范围：R-005。

### D-005：不支持旧版 KernelSU

- 状态：已确认
- 结论：启动时检测 `ksu.spawn`；缺失时显示升级提示，不提供同步 `exec` 回退。
- 理由：保留旧版回退会让旧环境继续出现相同卡顿，且难以让用户判断修复是否生效。
- 考虑过的备选：自动回退到 `exec` 并提示；自动回退但不提示。
- 未采用原因：两条路径的性能表现差异过大，不符合本次量化验收标准。
- 影响范围：R-002。

### D-006：只改前端

- 状态：已确认
- 结论：本次不修改 `box.tool task list` 或其他后端脚本，后端优化按修复后的实测结果另行决定。
- 理由：同步桥接和高频轮询已经解释当前卡顿；先收敛改动面，降低回归风险。
- 考虑过的备选：同时优化 `task list`；完全不优化。
- 未采用原因：后端改动需要额外 shell 回归测试；当前先验证前端根因修复。
- 影响范围：R-001 至 R-005、R-006。

## 8. 技术设计

### 8.1 模块与职责

- `webui/src/api/client.ts`：新增异步命令执行器 `execAsync()`，封装 `ksu.spawn()`、stdout/stderr 收集、退出码归一化和临时文件清理；`api` 对象保持现有方法签名。
- `webui/src/api/queries.ts`：调整任务、状态、日志的刷新策略；任务启动后通过查询缓存写入或 invalidate 触发轮询。
- `webui/src/app/shell.tsx`：拆分全局状态守卫查询，避免所有页面默认轮询状态。
- `webui/src/features/overview/overview-page.tsx`：概览只保留状态与快捷入口，不再查询日志。
- `webui/src/app/providers.tsx`：保持 React Query 全局默认，不引入新的全局状态库。

### 8.2 异步命令执行流程

```ts
async function execAsync(command: string) {
  // 通过 kernelsu.spawn('/system/bin/sh', ['-c', shellQuote(command)])
  // 收集 stdout/stderr，等待 exit；超时、spawn 失败和非零退出码交给上层处理
}
```

- `spawn` 的 `exit` 事件是唯一完成信号；`error` 事件仅记录错误，不能和 `exit` 重复结算 Promise。
- stdout/stderr 按行收集后以换行拼接，保持与现有 `exec()` 输出兼容。
- `runJsonWithFile` 的写入和清理也改用异步执行器。
- 应用启动时检查 `typeof window.ksu?.spawn === "function"`；缺失时渲染升级提示页。

### 8.3 轮询矩阵

| 查询 | 触发条件 | 间隔 | 停止条件 |
|---|---|---|---|
| `task list` | 应用启动/任务页/任务启动后 | 有 `running` 时 2 秒 | 无运行中任务 |
| `status` | 概览页可见或 mihomo 页面守卫缓存缺失 | 概览 15 秒；守卫仅一次 | 离开概览 |
| `logs` 概览 | 概览页可见 | 5 秒 | 离开概览 |
| `logs` 日志页 | 日志页可见且未暂停 | 2 秒 | 离开日志页或用户暂停 |
| `task logs` | 任务详情打开 | 2 秒 | 关闭详情或任务结束 |
