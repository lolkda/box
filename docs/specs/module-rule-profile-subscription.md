## 2. 目标与范围

### 背景

当前节点订阅只下载节点并生成 `proxy-providers`，不导入订阅返回的 `proxy-groups`、`rule-providers` 和 `rules`。用户提供的聚合订阅返回完整 mihomo 配置，另一个 `config.yaml` 地址只有策略组、规则集和规则；实测包含 22 个策略组、33 个规则集、49 条规则。

用户希望在保留节点订阅职责的同时，新增一个全局“规则与策略订阅”：单独维护一份规则模板 URL，将模板中的策略组、规则集和规则应用到当前 `config.yaml`，并在订阅页直接看到这些内容和 `config.yaml` 入口。

### 目标

- 增加全局规则模板 URL 的配置、读取和清除。
- 下载并校验规则模板 YAML，只接受 `proxy-groups`、`rule-providers`、`rules` 三段。
- 应用时替换 `config.yaml` 的这三段，保留 `proxy-providers`、端口、DNS、TUN 等其他配置。
- 订阅页新增“规则与策略订阅”卡片，显示掩码 URL、更新时间、当前策略组/规则集/规则数量和跳转入口。
- 每次应用前询问“仅保存”或“保存并重载”。
- 节点订阅行为保持不变。

### 非目标

- 不把 `proxy-groups`、`rule-providers`、`rules` 并入每个节点订阅。
- 不导入规则模板中的 `proxy-providers`。
- 不覆盖完整 `config.yaml`，不导入端口、DNS、TUN 等运行配置。
- 不自动合并用户手工添加的策略组、规则集或规则；应用时三段整体替换。
- 不新增任务中心任务类型；规则模板更新在订阅页内完成。
- 不支持需要额外认证头的规则模板 URL。

## 4. 行为要求与约束

### R-001：全局规则模板来源

- 参与者或触发方：订阅页“规则与策略订阅”卡片。
- 前置条件与输入：当前核心为 mihomo；用户输入 `http://` 或 `https://` 开头的规则模板 URL。
- 必须满足的行为：只保存一个全局规则模板 URL；URL 以掩码形式返回和展示；读取、修改、清除互不影响节点订阅。
- 输出或状态变化：`rule-profile get` 返回是否已配置、掩码 URL、最近应用时间、当前策略组/规则集/规则数量；`set` 和 `clear` 后卡片立即刷新。
- 边界与失败行为：非 http/https URL 返回 `E_VALIDATION`；非 mihomo 核心时返回不支持；URL 读取失败返回可读错误，不泄露完整 URL。

### R-002：规则模板下载与校验

- 参与者或触发方：规则与策略订阅的“更新规则与策略”按钮。
- 前置条件与输入：已配置规则模板 URL。
- 必须满足的行为：下载 URL 返回的 YAML，保存为待应用快照；校验顶层为 map 且包含 `proxy-groups`、`rule-providers`、`rules`，并复用现有策略组、规则集、规则引用校验。
- 输出或状态变化：校验成功后返回待应用快照的统计数量；原 `config.yaml` 不变。
- 边界与失败行为：下载失败、内容为空、YAML 非法、缺少三段或引用非法时返回明确错误；不覆盖待应用快照之外的文件，不修改 `config.yaml`。

### R-003：应用到 config.yaml

- 参与者或触发方：应用确认对话框。
- 前置条件与输入：存在已校验的待应用快照；用户选择“仅保存”或“保存并重载”。
- 必须满足的行为：只替换 `config.yaml` 的 `proxy-groups`、`rule-providers`、`rules`；保留 `proxy-providers` 及其他顶层配置；写入前生成 `config.yaml.bak`；写入后再次校验 YAML；按现有 `ruleset_prefix` 规则处理规则集 URL。
- 输出或状态变化：应用成功后更新最近应用时间；清除待应用快照；刷新策略组、规则、规则集和核心配置查询。
- 边界与失败行为：写入失败时还原备份；校验失败时还原备份；应用失败不更新最近应用时间；不修改节点 provider 文件。

### R-004：应用后重载

- 参与者或触发方：应用确认对话框。
- 前置条件与输入：待应用快照已校验；用户选择“保存并重载”。
- 必须满足的行为：写入成功后，如果服务正在运行，执行一次 mihomo reload；如果服务未运行，返回未重载状态；如果用户选择“仅保存”，不触发 reload。
- 输出或状态变化：成功时提示已保存并重载或已保存；reload 失败时返回错误详情，同时保留已写入配置和 `.bak`。
- 边界与失败行为：不得因为 reload 失败回滚或删除成功写入的配置；不得在“仅保存”路径触发热重载。

### R-005：订阅页入口与展示

- 参与者或触发方：订阅页。
- 前置条件与输入：mihomo 核心。
- 必须满足的行为：在订阅页顶部或节点订阅列表之前显示“规则与策略订阅”卡片；显示掩码 URL、最近应用时间、策略组/规则集/规则数量；提供配置/修改地址、更新、清除入口；提供进入策略组、规则、规则集、核心配置页面的链接。
- 输出或状态变化：未配置时显示说明和“配置规则订阅”；已配置时显示更新按钮；非 mihomo 核心时隐藏或显示不支持说明。
- 边界与失败行为：规则模板查询失败不阻塞节点订阅列表，只在卡片内显示错误；模板更新失败保留原卡片数据。

### R-006：安全与兼容

- 参与者或触发方：规则模板 URL 的存储、日志、页面和错误信息。
- 前置条件与输入：URL 可能包含 token 或查询参数。
- 必须满足的行为：页面只显示掩码 URL；日志中的规则模板 URL 和命令行参数 URL 都做脱敏；完整 URL 只在编辑输入框中回填；不把 URL 写入规则或错误详情。
- 输出或状态变化：无敏感信息出现在列表、任务日志或 toast 中。
- 边界与失败行为：节点订阅、`config apply`、`config.yaml` 编辑器的既有安全约束不变。

### R-007：节点订阅保持不变

- 参与者或触发方：节点订阅更新流程。
- 前置条件与输入：存在节点订阅或规则模板。
- 必须满足的行为：节点订阅仍只维护 `proxy-providers`；更新节点订阅不替换策略组、规则集和规则；规则模板更新不修改 `proxy-providers`。
- 输出或状态变化：两套来源各自更新，互不覆盖。
- 边界与失败行为：节点订阅更新失败不影响已应用的规则模板；规则模板更新失败不影响节点 provider。

### 相关约束

- 规则模板仅支持 mihomo。
- 复用现有 `config_validate_json`、`config_apply_json` 和 `ruleset_prefix` 逻辑。
- 不在 WebView 内解析大型 YAML；解析和写入由 `box.tool` 完成。
- 规则模板 URL 和个人订阅 URL 不写入仓库、测试夹具或日志。
- 规则模板应用仍是页面内操作，不新增 task kind。

## 5. 关键决定

### D-001：规则模板与节点订阅分离

- 状态：已确认
- 结论：新增一个全局规则模板 URL，节点订阅只维护 `proxy-providers`。
- 理由：多个节点源可以共用一套策略和规则，避免每个订阅各自覆盖 `config.yaml`。
- 考虑过的备选：每个节点订阅携带完整配置；两种都支持。
- 未采用原因：多订阅时冲突和覆盖不可控，且会破坏当前节点订阅职责。
- 影响范围：R-001、R-007。

### D-002：只导入三段

- 状态：已确认
- 结论：规则模板只使用 `proxy-groups`、`rule-providers`、`rules` 三段，不导入 `proxy-providers`、端口、DNS、TUN 等。
- 理由：节点来源和运行配置各有权威来源，避免互相覆盖。
- 考虑过的备选：完整覆盖 `config.yaml`；一并导入节点 provider。
- 未采用原因：会破坏模块运行配置和节点订阅数据。
- 影响范围：R-002、R-003、R-007。

### D-003：三段整体替换

- 状态：已确认
- 结论：应用时整体替换三段，不与现有手工内容自动合并。
- 理由：规则顺序、策略组引用和规则集引用必须保持一致，自动合并容易产生非法引用。
- 考虑过的备选：按名称合并；预览后选择性应用。
- 未采用原因：合并规则复杂且容易破坏引用；当前先提供可预测的托管行为。
- 影响范围：R-003。

### D-004：订阅页独立卡片

- 状态：已确认
- 结论：在订阅页新增“规则与策略订阅”卡片，并链接现有策略、规则、规则集和核心配置页面。
- 理由：符合用户对“订阅里包含规则和策略”的预期，也保留现有页面的完整编辑能力。
- 考虑过的备选：底部新增配置导航；仅放在更多页。
- 未采用原因：会改变底部导航或继续降低可发现性。
- 影响范围：R-005。

### D-005：独立更新，不进入任务中心

- 状态：已确认
- 结论：规则模板更新由订阅页按钮触发，下载、校验、确认和应用均在页面内完成。
- 理由：模板体积小，流程短；每次询问“仅保存/保存并重载”与后台任务化流程不匹配。
- 考虑过的备选：任务中心任务；下载在页面内、应用进任务中心。
- 未采用原因：增加两阶段交互和任务基础设施，当前收益不足。
- 影响范围：R-002、R-004、R-005。

### D-006：每次询问是否重载

- 状态：已确认
- 结论：应用前显示确认对话框，提供“取消 / 仅保存 / 保存并重载”。
- 理由：规则变更影响面较大，用户希望保留控制权。
- 考虑过的备选：总是自动重载；只保存不重载；使用普通二次确认。
- 未采用原因：不符合用户对“每次询问”的选择。
- 影响范围：R-004。

### D-007：仅支持 mihomo

- 状态：已确认
- 结论：规则与策略订阅只对 mihomo 显示和生效。
- 理由：`proxy-groups`、`rule-providers`、`rules` 是 mihomo 配置结构，当前项目只保留 mihomo 与 sing-box。
- 考虑过的备选：sing-box 也显示入口；转换为 sing-box 规则。
- 未采用原因：转换语义不等价，超出本次范围。
- 影响范围：R-001、R-005。

## 8. 技术设计

### 8.1 后端接口

在 `box/scripts/box.tool` 新增 `rule-profile` 子命令：

| 命令 | 用途 | 输出 |
|---|---|---|
| `rule-profile get --json` | 读取 URL、最近应用时间、当前三段数量 | `supported/configured/url_masked/updated_at/counts` |
| `rule-profile set <url> --json` | 保存掩码 URL | 同 `get` |
| `rule-profile url --json` | 编辑时读取完整 URL | `{url}` |
| `rule-profile clear --json` | 清除 URL、待应用快照、最近时间 | `{cleared:true}` |
| `rule-profile fetch --json` | 下载并校验模板到待应用快照 | `fetched_at/counts/url_masked` |
| `rule-profile apply [--reload] --json` | 应用待应用快照 | `changed/reloaded/counts` |

存储：

- URL：`/data/adb/box/mihomo/rule-profile.url`，权限 `0600`。
- 最近应用时间：`/data/adb/box/run/state/rule-profile.updated_at`。
- 待应用快照：`/data/adb/box/run/state/rule-profile.pending.yaml`。

复用：

- `config_validate_json`：校验三段结构、策略组名称/类型、规则集字段、规则引用。
- `config_apply_json`：备份 `config.yaml`、写入三段、YAML 回校验。
- `update_mihomo_rulesets`：应用 `ruleset_prefix`。
- `reload_if_running` 或 `reload`：按用户选择执行重载。

### 8.2 前端组件
