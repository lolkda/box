## 2. 目标与范围

### 背景

当前规则与策略订阅只有一条全局 URL，更新后待应用快照也只有一份。用户有多个机场和多个规则模板时，需要像节点订阅一样添加多条规则订阅，并明确选择其中一条使用；多条规则不能合并，否则策略组、规则顺序和规则集引用会互相覆盖。

节点订阅仍全部加载到 `proxy-providers`。规则模板是否使用某个机场的节点，由模板中的 `proxy-groups.use` / `include-all` 决定；本规格不把规则订阅绑定到某个节点订阅。

### 目标

- 支持多条命名规则订阅的添加、编辑、删除、更新和查看。
- 同一时间只有一条处于“当前使用”；应用时只写这一条的三段，绝不合并多条规则。
- 每条规则订阅有独立的待应用快照；更新只下载/校验，不直接写 `config.yaml`。
- 点“使用”应用选中条目的快照；没有快照时自动下载。应用前仍询问“仅保存 / 保存并重载”。
- 当前使用标记只在配置写入成功后变更；更新当前条目但未应用时显示“待应用”。
- 禁止直接删除当前使用的条目；先停用或切换到另一条。
- 现有单条 URL 自动迁移为“默认规则”，不丢失配置。
- 规则 Tab 从单卡片改为列表，节点/规则仍分 Tab。

### 非目标

- 不把多条规则订阅合并应用。
- 不把规则订阅绑定到某个节点订阅，不自动过滤其他机场节点。
- 不自动更新规则订阅，不引入定时任务。
- 不改变节点订阅的下载、provider 生成和更新流程。
- 不改变规则模板只接受 `proxy-groups`、`rule-providers`、`rules` 三段的约束。

## 4. 行为要求与约束

### R-001：多规则订阅列表

- 参与者或触发方：规则 Tab、`rule-profile` 命令。
- 前置条件与输入：mihomo 核心；用户添加名称和 http/https URL。
- 必须满足的行为：支持多条规则订阅；每条有稳定 ID、显示名称、掩码 URL、独立待应用快照和更新时间；任意时刻最多一条“当前使用”；不得把多条规则合并。
- 输出或状态变化：列表返回条目、当前使用标记、待应用标记、数量和最近应用时间。
- 边界与失败行为：名称不能为空；转换后的 ID 冲突时拒绝或生成唯一 ID；URL 非法时拒绝；sing-box 返回不支持状态。

### R-002：添加、编辑、删除与停用

- 参与者或触发方：规则 Tab 的添加/编辑/删除/停用操作。
- 前置条件与输入：名称、URL；删除或停用目标条目。
- 必须满足的行为：添加只保存 URL，不自动写配置；编辑可改名称/URL；当前使用的条目禁止直接删除；停用只清除当前标记，不修改 `config.yaml`；删除非当前条目同时删除其快照和元数据。
- 输出或状态变化：列表更新；当前使用标记和待应用状态保持真实。
- 边界与失败行为：当前使用条目删除返回 `E_VALIDATION`；停用不删除条目，不改变配置；URL 变化后旧快照失效。

### R-003：更新与使用

- 参与者或触发方：规则 Tab 的更新/使用操作。
- 前置条件与输入：选中条目的 URL；已有快照或需要自动下载。
- 必须满足的行为：更新只下载、校验、保留 DNS 引用并写待应用快照，不修改 `config.yaml`；使用优先应用已下载快照，没有快照时先下载；应用仍只替换三段并生成 `.bak`；应用前询问“仅保存 / 保存并重载”；当前使用标记只在配置写入成功后变更；重载失败不回滚已写入配置，返回明确错误。
- 输出或状态变化：更新后显示待应用；使用后清除待应用、更新应用时间并切换当前使用；其他条目保持不变。
- 边界与失败行为：下载/校验失败保留旧快照和当前使用；应用失败不切换当前使用；重载失败保留配置和当前使用标记，并返回 `E_RELOAD`。

### R-004：迁移单条规则订阅

- 参与者或触发方：升级后首次读取规则订阅。
- 前置条件与输入：存在旧 `rule-profile.url`、待应用快照或 `rule-profile.updated_at`。
- 必须满足的行为：自动迁移为 ID `default`、名称“默认规则”的条目；旧 URL 和快照不丢失；旧 `updated_at` 存在时标记为当前使用；迁移失败不删除旧文件。
- 输出或状态变化：列表出现迁移条目；旧命令仍能读取当前/首条。
- 边界与失败行为：重复迁移幂等；旧文件不存在时创建空列表。

### R-005：规则 Tab 列表 UI

- 参与者或触发方：`/subscriptions/rule-profile`。
- 前置条件与输入：规则订阅列表数据。
- 必须满足的行为：与节点订阅卡片保持一致；添加是右上角 `+` 图标按钮，不显示规则来源图标（订阅本身不提供图标）；条目列表显示名称、掩码 URL、当前使用/待应用徽标、更新时间、策略组/规则集/规则数量和输出链接；使用、更新、编辑、停用、删除收进卡片右上角更多菜单，卡片内不放大按钮；当前使用条目不可删除。
- 输出或状态变化：空列表显示配置入口；更新/使用后刷新列表和配置相关查询。
- 边界与失败行为：列表查询失败不阻塞节点 Tab；错误显示在规则 Tab；URL 不回显完整值。

### R-006：安全与兼容

- 参与者或触发方：规则订阅 URL、文件、日志和错误。
- 前置条件与输入：URL 可能包含 token；名称可能包含路径字符。
- 必须满足的行为：URL 文件权限 `0600`；列表/日志/错误只显示掩码 URL；完整 URL 只在编辑请求中返回；名称转换后的 ID 不越出规则订阅目录；旧 `get/set/url/fetch/apply` 命令继续可操作当前或首条。
- 输出或状态变化：无敏感信息出现在列表、任务日志或 toast 中。
- 边界与失败行为：非法名称、URL 或 ID 拒绝；不读取目录外文件。

### R-007：节点范围保持独立

- 参与者或触发方：规则应用与节点订阅更新。
- 前置条件与输入：存在多个节点订阅。
- 必须满足的行为：规则订阅不修改 `proxy-providers`；节点订阅不修改当前规则；应用某条规则时所有节点 provider 仍加载；具体使用哪些机场由模板 `use` / `include-all` 决定。
- 输出或状态变化：规则与节点两套来源互不覆盖。
- 边界与失败行为：规则应用失败不影响节点 provider；节点更新失败不影响当前规则。

### 相关约束

- 仅支持 mihomo；复用 `config_validate_json`、`config_apply_json`、`rule_profile_preserve_dns_providers` 和 `upfile`。
- 不把完整 URL 写入仓库、测试夹具或日志。
- 规则模板仍只允许三段；应用时不导入 `proxy-providers`。

## 5. 关键决定

### D-001：独立规则订阅列表，单选使用

- 状态：已确认
- 结论：规则订阅是独立列表，同一时间最多一条当前使用；不把多条规则合并。
- 理由：多条规则同时生效会破坏策略组、规则顺序和规则集引用；独立列表符合“像节点订阅一样添加”的预期。
- 考虑过的备选：规则订阅绑定节点订阅；多规则同时启用。
- 未采用原因：绑定会降低规则复用；同时启用无法保证引用一致。
- 影响范围：R-001、R-003、R-007。

### D-002：更新暂存，使用应用

- 状态：已确认
- 结论：更新只写待应用快照；使用才应用快照；没有快照时使用会自动下载；应用前询问仅保存/重载。
- 理由：把下载校验和修改运行配置分开，避免切换列表时隐式改配置。
- 考虑过的备选：使用只改标记；使用总是重新下载；更新即应用。
- 未采用原因：标记/配置会不一致；总是下载慢；更新即应用缺少确认。
- 影响范围：R-003、AC-003、AC-004。

### D-003：当前使用条目禁止直接删除

- 状态：已确认
- 结论：删除当前使用条目返回错误；先停用或使用另一条；停用只清标记，不改配置。
- 理由：删除和配置变更不应隐式发生；保留真实状态。
- 考虑过的备选：删除后保留旧配置；自动回退上一条。
- 未采用原因：当前标记会悬空或隐式改配置。
- 影响范围：R-002、AC-005。

### D-004：迁移为默认规则

- 状态：已确认（模型决定）
- 结论：旧单条 URL 迁移为 ID `default`、名称“默认规则”；旧 `updated_at` 存在则标记当前使用。
- 理由：升级不丢配置，且不伪造“已应用”状态。
- 影响范围：R-004、AC-006。

### D-005：目录与文件布局

- 状态：已确认（模型决定）
- 结论：规则订阅保存在 `mihomo/rule-profiles/`；每个 ID 使用 `.url`、`.name`、`.pending.yaml`、`.fetched_at`、`.applied_at`、`.counts`；`active` 文件保存当前 ID。
- 理由：无需数据库；文件可原子替换；与现有 shell 工具兼容。
- 考虑过的备选：单个 JSON 注册表；SQLite。
- 未采用原因：shell 下 JSON 并发/部分写入更难；SQLite 增加依赖。
- 影响范围：R-001、R-004、R-006。

### D-006：不绑定节点订阅

- 状态：已确认
- 结论：规则订阅不包含节点订阅字段；所有节点 provider 继续加载；模板决定使用范围。
- 理由：规则可跨机场复用；绑定会引入 1:1 限制和组过滤复杂度。
- 考虑过的备选：每条规则绑定机场；可选绑定。
- 未采用原因：用户选择“只指定规则”，当前阶段不做节点隔离。
- 影响范围：R-007、AC-009。

## 8. 技术设计

### 8.1 后端存储

```text
${mihomo_config%/*}/rule-profiles/
  active                 # 当前使用的 ID，一行
  <id>.url               # 0600
  <id>.name              # 显示名称
  <id>.pending.yaml      # 待应用快照
  <id>.fetched_at
  <id>.applied_at
  <id>.counts            # {"groups":N,"rule_providers":N,"rules":N}
```

- ID 使用现有 `sub_provider_file_name` 规则转换；添加/编辑时检查重名与 ID 冲突。
- 迁移旧 `mihomo/rule-profile.url`、`run/state/rule-profile.pending.yaml`、`run/state/rule-profile.updated_at` 到 `default` 条目。
- URL、快照和计数文件均限制在目录内，拒绝路径穿越。

### 8.2 命令

```text
rule-profile list --json
rule-profile add <name> <url> --json
rule-profile edit <id> <name> <url> --json
rule-profile url <id> --json
rule-profile update <id> --json
rule-profile use <id> [--reload] --json
rule-profile remove <id> --json
rule-profile deactivate --json
rule-profile get --json                 # 兼容：当前或首条
rule-profile set <url> --json           # 兼容：当前或首条
rule-profile fetch [<id>] --json        # 兼容：当前或首条
rule-profile apply [<id>] [--reload] --json
```

- `list` 返回 `supported/items`；条目含 `id/name/url_masked/active/pending/fetched_at/applied_at/counts/can_delete`。
- `update` 只写 pending、counts、fetched_at；`use` 应用 pending，写 active、applied_at，成功后删除 pending。
- `remove` 当前条目返回 `E_VALIDATION`；`deactivate` 只删除 active 文件。
- 旧 `set` 在当前/首条上更新 URL；旧 `fetch/apply` 对当前/首条操作。
