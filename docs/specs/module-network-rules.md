## 2. 目标与范围

### 背景

当前模块的网络绕过和代理规则分散在 `rust/crates/boxctl/src/network.rs` 的多个函数中，常见的私网、IPv6、DNS、ADB、接口和保留地址都以 Rust 常量或固定分支生成。实际使用中已经出现两类问题：

- ADB 无线调试等本机服务被代理规则截断，只能在设备上补规则；
- 用户看到不合适的 CIDR、端口或接口规则，无法在 WebUI 中增删改，只能等待模块发版。

规则既需要保留安全不变量，也需要让用户按行管理自己的策略，而不是暴露原始 iptables 文本。

### 目标

- 把可变的网络绕过/阻断规则从 Rust 常量迁移到版本化数据文件。
- 在 WebUI「更多 > 网络规则」提供一行一条规则的新增、修改、删除、启停、排序和预览应用。
- 内置规则可见、可编辑、可禁用、可删除；删除使用 tombstone，模块升级不复活，支持恢复默认。
- 自动保护规则（核心旁路、`--dst-type LOCAL`、动态本机地址、ADB 动态端口等）只读展示，不可由用户删除。
- 预览显示语义差异和实际生成的 iptables 计划；应用使用 revision 校验、原子写入和失败回滚。
- 保持现有五种网络模式、DNS 拆分、规则清理和服务启动流程可用。

### 非目标

- 不实现任意 iptables/nft 参数文本编辑。
- 不开放用户修改 `BOX_*` 链结构、hook 顺序、核心 mark、`ip rule`/`ip route` 或 DNS 链拆分。
- 不实现域名匹配；域名仍由 mihomo 规则处理，系统网络规则只做 IP/端口/接口/UID/GID/目标类型匹配。
- 本轮不把 nft 作为 P0 验收路径；iptables 优先，nft 路径保持可编译但不作为 `.33` 验收条件。
- 不实现多用户权限、远程 HTTP 管理或跨设备草稿同步。
- 不自动提交、推送或发布任何 Git 变更。

## 4. 行为要求与约束

### R-001：规则数据文件与修订号

- 参与者或触发方：`boxctl` 守护进程、WebUI 网络规则页、启动流程。
- 前置条件与输入：模块根目录可写；规则文件不存在、为空、损坏或为旧版本。
- 必须满足的行为：
  - 用户规则使用版本化 JSON 文件，默认路径为 `run/state/network-rules.json`，默认规则另存为模块包内的 `network-rules.default.json`。
  - 文件包含 `schema_version`、`revision`、`defaults_version`、`rules` 和 `tombstones`。
  - 缺失文件时从默认规则播种；损坏文件返回明确诊断，不静默覆盖原文件。
  - 每次成功应用递增 `revision`；写入使用临时文件、fsync 和原子 rename。
  - 读取结果包含当前 revision，供后续预览和应用做乐观并发校验。
- 输出或状态变化：规则文件存在且可解析；revision 单调递增；损坏文件保留并报告。
- 边界与失败行为：未知 schema 版本、字段类型错误、重复 ID、非法模式或非法作用层均拒绝；写入失败不改变原文件。

### R-002：默认规则、tombstone 与恢复操作

- 参与者或触发方：首次安装、模块升级、WebUI 删除/恢复/清空操作。
- 前置条件与输入：默认规则文件存在；用户规则文件已加载。
- 必须满足的行为：
  - 首次安装播种完整默认规则集，包含 IPv4 私网/保留段、IPv6 本地段、DHCP/mDNS/SSDP、ADB 和本机旁路。
  - 用户编辑默认规则后保留其修改，不因升级被默认文件覆盖。
  - 用户删除默认规则时写入 tombstone；后续升级不复活该 ID。
  - 升级只自动补入尚未出现过且未被 tombstone 的新默认 ID。
  - `恢复默认规则` 恢复默认规则集并保留自定义规则；`清空全部规则` 删除自定义和默认规则，但只读系统保护始终存在；清空后 default 规则可再次恢复。
  - `恢复默认规则` 不删除自定义规则，`清空全部规则` 需要二次确认。
- 输出或状态变化：规则数组、tombstone 和默认版本一致；恢复/清空后 revision 递增。
- 边界与失败行为：默认文件缺失时保留现有用户规则并报告；恢复/清空写入失败时规则文件不变。

### R-003：语义化规则字段和匹配

- 参与者或触发方：WebUI 规则表单、API 校验器、iptables 计划编译器。
- 前置条件与输入：用户提交一条或多条规则。
- 必须满足的行为：
  - 每条规则包含稳定 `id`、`name`、`enabled`、`action`、`scopes`、`modes`、`family`、`protocol` 和 `match`。
  - 动作为 `bypass` 或 `reject`；`bypass` 生成 `RETURN`，`reject` 生成 `REJECT`。
  - 匹配字段支持：`dst_cidrs`、`src_cidrs`、`dst_ports`、`src_ports`、`src_ifaces`、`dst_ifaces`、`uids`、`gids`、`dst_types`。
  - 同一字段内的多个值按 OR；不同字段之间按 AND。
  - 支持 IPv4、IPv6 和双栈；端口支持单端口和闭区间（如 `137-139`）；CIDR、端口、UID/GID、接口和目标类型均需校验。
  - 不接受任意 iptables 参数、shell 文本、域名或未知字段。
- 输出或状态变化：规则被规范化为稳定 JSON；预览和计划只使用规范化后的值。
- 边界与失败行为：空匹配不是合法规则；`reject` 只允许本机/转发/过滤作用层；IPv6 字段在平台缺少 `ip6tables` 时产生可恢复告警而不是伪造成功。

### R-004：作用层、执行顺序与系统保护

- 参与者或触发方：规则编辑器、计划编译器、网络应用。
- 前置条件与输入：规则已通过字段校验。
- 必须满足的行为：
  - 作用层取值为 `local`（本机 OUTPUT）、`forward`（转发/TUN）、`dns`、`filter`。
  - 一条规则可以选择多个作用层；按其在数组中的位置分别进入每个作用层的用户规则序列。
  - 系统保护规则在每个作用层固定先于用户规则；用户不能编辑、删除或重排系统保护。
  - 用户规则只能调整自身相对顺序，不能把规则移动到系统保护之前。
  - 删除、禁用、排序不需要重启 mihomo 核心。
- 输出或状态变化：生成的计划中每个作用层的顺序稳定可复现。
- 边界与失败行为：非法作用层组合、把 `reject` 放入 DNS 链、引用未知作用层均拒绝。

### R-005：模式与平台能力

- 参与者或触发方：规则编辑器、网络计划执行。
- 前置条件与输入：规则包含 `modes`；当前 `network_mode` 和能力探测结果已读取。
- 必须满足的行为：
  - `modes` 是 `tun`、`tproxy`、`redirect`、`mixed`、`enhance` 的非空子集；默认全选。
  - 计划只为当前模式包含的规则生成执行项；非当前模式的规则保留在文件中。
  - 能力不足时按平台策略告警/降级，不伪造 iptables 成功。
- 输出或状态变化：预览显示“当前模式是否生效”；应用后在切换模式时按规则 `modes` 重新编译。
- 边界与失败行为：模式非法或为空时拒绝；缺失 ip6tables 时 IPv6 规则告警并跳过，不阻断 IPv4。

### R-006：预览、应用、revision 与回滚

- 参与者或触发方：WebUI 的预览/应用按钮、CLI。
- 前置条件与输入：完整规则文档或变更后的规则数组；客户端持有的 base revision。
- 必须满足的行为：
  - `preview` 不写规则文件、不执行 iptables，返回语义差异、告警和生成的计划摘要。
  - `apply` 必须校验 base revision；revision 不一致返回冲突，不覆盖其他人的修改。
  - 应用顺序为：校验完整文档 → 生成计划 → 原子写规则文件 → 若服务运行则应用计划；任一步失败按已应用步骤回滚。
  - 服务停止时 `apply` 只持久化规则，返回“下次启动生效”，不启动核心。
  - 应用成功返回新 revision 和实际执行状态。
- 输出或状态变化：规则文件 revision 更新；服务运行时的网络规则与新文档一致；失败时文件与网络状态回到应用前。
- 边界与失败行为：校验失败、revision 冲突、iptables 命令失败、写文件失败均不得留下半应用状态；错误包含失败字段/命令摘要。

### R-007：WebUI 行级增删改、启停与排序

- 参与者或触发方：WebUI 网络规则页。
- 前置条件与输入：用户点击新增、编辑、删除、启用/禁用、上移/下移或拖拽。
- 必须满足的行为：
  - 每条用户规则以单行卡片展示名称、动作、作用层、模式摘要、匹配摘要和启用状态。
  - 行操作提供编辑、启用/禁用、删除；删除需确认；新增/编辑使用底部 Sheet 或等价移动端表单。
  - 基础字段首屏展示：名称、动作、作用层、模式、协议、目标 CIDR、目标端口。
  - 高级条件折叠展示：源 CIDR、源/目标端口、源/目标接口、UID、GID、目标类型；字段可放多个标签。
  - 系统保护区只读展示，不提供编辑、删除、拖拽控件。
  - 所有行操作只修改前端草稿，不直接执行 iptables。
- 输出或状态变化：草稿状态变化；页面显示未应用修改数量。
- 边界与失败行为：表单校验失败时阻止保存草稿并指出具体字段；删除最后一条规则不影响系统保护。

### R-008：前端草稿持久化

- 参与者或触发方：WebUI 页面加载、导航、刷新。
- 前置条件与输入：用户已有未应用修改。
- 必须满足的行为：
  - 草稿保存在浏览器 `localStorage`，包含 base revision、规则数组、tombstone 和保存时间。
  - 返回页面时恢复草稿并显示“有未应用修改”；提供“丢弃草稿”。
  - 成功 apply 后清除草稿；revision 冲突时保留草稿并要求用户重新加载/合并。
  - 草稿不写服务端，不自动应用。
- 输出或状态变化：刷新或切换页面后未应用编辑仍在；应用成功后消失。
- 边界与失败行为：localStorage 不可用或数据损坏时回退到服务端规则并提示；不得把损坏草稿发送到 apply。

### R-009：预览界面与差异

- 参与者或触发方：用户点击预览/应用。
- 前置条件与输入：当前草稿与服务端 base revision。
- 必须满足的行为：
  - 预览显示新增、修改、删除、排序、启停的数量。
  - 预览按作用层展示将要生成的计划摘要，并显示系统保护项。
  - 显示阻塞错误和告警；有阻塞错误时不能应用。
  - 应用失败显示服务端错误和回滚结果，保留草稿。
- 输出或状态变化：用户能判断变更影响后再应用；失败后不丢失草稿。
- 边界与失败行为：预览请求失败、网络断开、服务端 revision 冲突时给出明确错误。

### R-010：默认规则迁移与 legacy 对齐

- 参与者或触发方：模块升级、首次读取规则。
- 前置条件与输入：旧版本没有 `network-rules.json`；默认规则文件包含 legacy 对齐集合。
- 必须满足的行为：
  - 首次启动创建与 legacy 等价的默认 CIDR/端口/接口规则，而不是继续从 Rust 常量读取。
  - 默认规则覆盖：IPv4 私网和保留段、IPv6 本地/保留段、DHCP、mDNS、SSDP、NetBIOS/LLMNR、ADB/本机旁路。
  - 规则编辑器展示默认规则的来源标记；修改后仍关联 default ID。
  - 删除默认规则写入 tombstone，升级时不恢复。
- 输出或状态变化：用户规则文件包含完整默认集；网络计划不再依赖散落的策略常量。
- 边界与失败行为：默认文件缺失时保留当前用户规则并产生可诊断告警；不得静默生成空规则集。

### R-011：服务启动、停止与规则应用集成

- 参与者或触发方：`service start/stop`、模式切换、网络规则 apply。
- 前置条件与输入：规则文件存在；服务运行状态已知。
- 必须满足的行为：
  - `service start` 读取规则文件和系统保护，编译当前模式的计划。
  - `service stop` 清理本模块拥有的规则和策略路由，不删除规则文件。
  - 运行中 apply 只替换本模块规则，不重启 mihomo；失败回滚。
  - 停止状态 apply 不启动核心，规则在下次 start 生效。
- 输出或状态变化：网络状态与规则文件一致；停止后无本模块残留。
- 边界与失败行为：服务状态读取失败时拒绝在线应用并提示；清理失败保留诊断，不假装成功。

### R-012：API、CLI 与权限边界

- 参与者或触发方：WebUI、`boxctl` CLI、Unix socket 守护进程。
- 前置条件与输入：请求来自本机 root/模块 WebUI。
- 必须满足的行为：
  - 提供 `network-rules get/preview/apply/reset/clear` CLI 子命令和对应守护进程方法。
  - `preview`/`apply` 接收完整规则文档和 base revision；`apply` 使用 JSON 响应返回新 revision。
  - `reset --defaults` 恢复默认并保留自定义；`reset --all` 清空所有规则。
  - 所有响应使用现有 NDJSON v2 envelope，错误使用明确 code。
  - 不接受原始 iptables 文本、未知字段或非法作用层。
- 输出或状态变化：CLI 和 WebUI 对同一规则文件得到一致结果。
- 边界与失败行为：权限不足、socket 不可用、无效 JSON、revision 冲突、默认文件缺失均返回可读错误，不修改规则文件。

### 相关约束

- 现有 `legacy-rust-remediation-plan.md` 要求 iptables 为 P0，nft 不作为本轮真机验收路径。
- 现有 `rust-script-migration.md` 要求网络规则通过计划器生成、失败可回滚，不直接散落 shell 命令。
- 规则文件属于用户数据，模块升级不得覆盖；默认规则属于模块数据，升级可以替换。
- Android 设备可能缺少 `ip6tables nat`；IPv6 降级必须有告警。

## 5. 关键决定

### D-001：规则使用语义化模型

- 状态：已确认
- 结论：规则只支持受限字段和 `bypass`/`reject` 动作，不支持原始 iptables 文本。
- 理由：可校验、可预览、可回滚，避免 WebUI 变成危险脚本编辑器。
- 考虑过的备选：仅地址/端口；原始 iptables。
- 未采用原因：能力不足或安全/维护成本过高。
- 影响范围：R-003、R-006、R-007。

### D-002：内置规则可编辑、禁用、删除并恢复默认

- 状态：已确认
- 结论：默认规则作为可编辑行播种；删除写 tombstone；提供恢复默认和清空全部两个操作。
- 理由：满足增删改，同时允许恢复。
- 考虑过的备选：内置只读；只能禁用；恢复默认即清空。
- 未采用原因：不满足用户可管理性，或语义过于破坏性。
- 影响范围：R-002、R-010、R-007。

### D-003：显式顺序

- 状态：已确认
- 结论：数组顺序即同一作用层内的执行顺序；WebUI 支持拖拽/上下移动。
- 理由：iptables 顺序直接影响结果，显式顺序可预测。
- 考虑过的备选：数字 priority；固定分类顺序。
- 未采用原因：WebUI 不直观或灵活性不足。

## 8. 技术设计

### 8.1 数据文件

用户规则：

```text
/data/adb/box/run/state/network-rules.json
```

默认规则随模块包发布：

```text
/data/adb/box/network-rules.default.json
```

用户文件是唯一可写数据源；默认文件只作为播种、升级补项和恢复默认的输入。两者都使用 `schema_version=1`，用户文件额外维护 `revision`、`tombstones` 和 `defaults_version`。

### 8.2 规则对象

```json
{
  "id": "user-...",
  "name": "局域网旁路",
  "enabled": true,
  "action": "bypass",
  "scopes": ["local", "forward"],
  "modes": ["tun", "tproxy", "redirect", "mixed", "enhance"],
  "family": "both",
  "protocol": "any",
  "match": {
    "dst_cidrs": ["192.168.0.0/16"],
    "dst_ports": ["5353"]
  },
  "origin": "user"
}
```

`match` 内字段之间 AND，每个字段的值之间 OR。`bypass` 编译为 `RETURN`，`reject` 编译为 `REJECT`；`reject` 只进入 filter 表，`dns` 只接受 `bypass`。

### 8.3 作用层映射

| 作用层 | 目标 |
|---|---|
| `local` | 本机 OUTPUT 的代理前旁路、过滤链 |
| `forward` | PREROUTING / TUN bypass / redirect 链 |
| `dns` | `BOX_DNS` / `BOX_DNS_PRE` 的端口 53 旁路 |
| `filter` | `BOX_FILTER_LOCAL` / `BOX_FILTER_PRE` 的拒绝规则 |

系统保护在每个作用层固定先于用户规则；用户规则顺序来自数组顺序，前端上下移动/拖拽等价于调整数组。

### 8.4 API 与 CLI

CLI：

```text
boxctl network-rules get --json
boxctl network-rules preview <json> --json
boxctl network-rules apply <json> --json
boxctl network-rules reset --json
boxctl network-rules reset all --json
boxctl network-rules clear --json
```

daemon 方法：

| 方法 | 请求 | 成功响应 | 主要错误 |
|---|---|---|---|
| `network_rules.get` | 空 | `GetResult` | `E_CONTENT`、`E_IO` |
| `network_rules.preview` | `{base_revision, rules, tombstones}` | `{document, diff, warnings}` | `E_VALIDATION`、`E_CONFLICT` |
| `network_rules.apply` | 同上 | 规则文档 + `applied` | `E_VALIDATION`、`E_CONFLICT`、`E_COMMAND` |
| `network_rules.reset` | `{all: bool}` | 规则文档 | `E_IO`、`E_COMMAND` |

`apply` 在服务运行时依次执行：校验 → 清理本模块旧规则 → 生成新计划 → 应用；失败时清理新计划并尝试恢复旧计划。服务停止时只写规则文件，不启动核心。

### 8.5 WebUI

- 路由：`/network-rules`，入口「更多 > 网络规则」。
- 系统保护卡片只读；用户规则卡片支持启停、编辑、删除、上移/下移。
- 编辑 Sheet：基础字段 + 高级折叠；字段均为标签输入或选择器，没有原始 iptables 文本。
- 未应用修改保存到 `localStorage` key `box.network-rules.draft.v1`，包含 base revision；应用成功清除，revision 冲突显示重新加载/丢弃。
- 预览卡片显示差异数量、告警、应用按钮；预览请求不写规则文件或 iptables。

### 8.6 默认规则与 tombstone

- 首次读取用户文件不存在时，从默认文件播种；默认规则 `origin=default`。
- 删除默认规则时同时写 tombstone；`load` 跳过该 ID。
- 模块升级只补入不在用户规则和 tombstone 中的新默认 ID；用户修改保留。
- `reset` 恢复默认并保留自定义；`reset all`/`clear` 清空规则并 tombstone 全部默认 ID；系统保护不受影响。
